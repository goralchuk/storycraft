# Phase 8.10 — Observability

Result of ROADMAP task 8.10. Generation is now diagnosable from the logs: each
stage and each external AI call leaves a trace, and a failure names where it broke.
OpenSpec change: `generation-observability` (modifies `generation-progress`).

## Per-AI-call logging

A small helper `ai/logged-call.ts` times an external call and logs its kind, model,
latency and outcome:

```
[AICall] text qwen3.7-plus ok in 4213ms
[AICall] image qwen-image-2.0 ok in 8120ms
[AICall] vision qwen3-vl-flash failed in 1900ms: ServiceUnavailableException: Vision checker error (429): ...
```

It wraps the three Qwen generators (text / image / vision). A slow or failing
provider call is now visible without adding logging to every call site.

## Per-stage logging

The worker logs one line per stage (tagged with the book id), a `DONE` summary, and
on failure an error naming the stage and elapsed time:

```
[<id>] generation started (16p)
[<id>] HEROES (reference=yes)
[<id>] STORY
[<id>] ILLUSTRATIONS (images=11/16)
[<id>] ASSEMBLE
[<id>] DONE in 94210ms (pages=16 images=11 regen=2)
```

On failure:

```
[<id>] FAILED at ILLUSTRATIONS in 21ms: Error: stub image failure
```

`regen` counts pages whose illustration was regenerated by the 8.5 QC pass
(detected when QC returns a different image key). `stage` mirrors the persisted
stage, so the failure line and the stored `stage` (8.8) agree.
